## Inspect or replay

Run from this folder using an existing Python installation:

```powershell
python -B replay.py
```

The default mode needs only Python's standard library. It verifies SHA256SUMS,
the exact frozen API archive and all 226 archived source members, project demo
asset bytes/canonical hashes, and exported immutable source bodies.

For canonical historical output replay, use an existing GroundTruth API dependency
environment. No Torch, model files, network, API or database is needed:

```powershell
python -B replay.py --canonical
```

The script imports the **bundled source27 implementation directly from its ZIP**,
without extraction or temporary directories, rather than using the current
checkout. That implementation is pinned to archive SHA256
`1b1a163a40e4bc7883b204e0ef48b0c4bd40a8d82a8051c6039c40112f53e142`.
Its API dependency/lock files remain inside the archive. This export does not
install dependencies. A small importer supplies locations for implicit namespace
packages omitted as directory entries in the original ZIP; all executable API
source bytes remain unchanged and pinned. The export writer ran the replay with the existing
development environment without Torch; see `export-validation.json`.

Canonical mode checks the nine completed connected records plus both repaired
restart records against independently extracted immutable public-demo versions,
actual requests/answers/citations and actual retained retrieval traces. It checks
three refusals, nine source responses, both historical phases' structural equality,
two missing-assets error records, repaired SSE token/citation parity, and rejects
22 in-memory changed-answer/certificate controls. It verifies captured evidence,
not the classifier's general semantic correctness or current live authorization.

## Files and provenance

- `actual-records.zip`: original JSON capture **file bytes** preserved losslessly
  under logical `connected/` and `restart/{missing,repaired}/` names. IDs, answers,
  quoted text, certificates, assessment values and retrieval traces are unchanged.
  Captures represent parsed HTTP responses/SSE event data, not network packet bytes.
- `public-source-snapshots.json.gz`: newly serialized authoritative version/chunk
  snapshots extracted through SQLite `mode=ro&immutable=1` from sealed297, bounded
  to the nine referenced public-demo versions. Each complete body is checked
  against `public-demo-assets/manifest.json`; no identity or literal is rewritten.
- `verifier/`: previously public source27 API archive and source manifest. This is
  historical source, not a new implementation or a model package.
- `public-demo-assets/`: exact project engineering inputs and upload/canonical hash
  manifest. Cedar/Juniper families are exposed engineering material, unsuitable
  for a fresh blind set.
- `protocol/`: the actual connected test/configs, capture script and restart probe.
  These are inspected historical protocols, **not** commands invoked by replay.
- `bindings/`: build manifests, runtime/source/model/protocol binding records.
  Interpreter/cache paths and build-manifest roots in generated descriptive
  bindings use logical aliases; captured file hashes remain unchanged.
- `independent/`: selected review299/review304 reports and machine-readable replay
  observations. Review statements retain their original bounded scope. Markdown
  line endings are normalized to LF for Git stability; original input digests
  remain in the bindings. The JSON observations retain their original file bytes.
- `screenshots/`: 12 original post-connect PNGs inspected by the export writer,
  with each state at all three widths. No key entry or authentication panel appears.
- `manifest.json` and `SHA256SUMS`: exact export membership/hashes. SHA256SUMS
  includes the manifest but excludes itself. These are unsigned integrity records,
  not cryptographic server or execution attestation.

Original versus replay serialization is explicit: the Q298 and restart files are
not claimed byte-equal to one another. The old DTOs compare as parsed objects with
exact literal strings, while each exported capture file separately retains its
original bytes. The source snapshots and descriptive runtime/binding records use
new documented JSON serialization. Original input digests and observation aliases
are retained without seed data or credentials.
