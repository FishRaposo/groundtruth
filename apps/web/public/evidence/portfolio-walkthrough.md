# GroundTruth walkthrough

## Recruiter tour: approximately three minutes

Open the landing page and read **Ask an operational question. Inspect the
evidence before trusting the answer.** The **Interactive sample data** banner is
visible throughout. Select **Start guided demo**, or **Explore freely** to
navigate without the tour.

1. Ask the suggested staging rollback question. Explain the question → retrieval
   → evidence → answer stages before expanding technical scores.
2. Open a citation with the keyboard. Read the highlighted captured passage;
   inspect version/hash details, close with Escape and confirm focus returns.
3. Compare the outdated runbook with the current procedure. The preview uses
   explicitly saved synthetic outcomes, not a claimed live benchmark.
4. Try the unsupported question and curated procedural conflict. Explain refusal
   and human review without suggesting universal contradiction detection.
5. Open Documents and follow quarantined-file recovery. It is simulated; choosing
   a local file does not transmit its contents in sample mode.
6. Inspect consistent Workflows/Admin state, then select **Run the actual project**
   or the workflow/evidence link. Reset restores every sample surface together.

## Actual workflow: approximately five minutes after setup

Follow [the connected setup](portfolio-connected.md) with a disposable database.
Open **Connection**, enter the locally generated key and choose **Connect
application**. The banner now names the connected local application and runtime
modes. No action submits a provider request.

Create a conversation. Ask “How do I roll back the staging deployment?” and open
the real saved citation. Inspect the exact source and version, reload the saved
query URL, then repeat using SSE. Explain that the answer consists of relevant
source extracts, with bounded support checks and measured coverage limitations.

Upload a small TXT/PDF. Inspect the completed real ingestion job. Replace the
content with a file of the same format, compare versions, inspect the old passage
and explicitly restore it. The restored publication is a new revision, not an
overwrite of historical evidence. Upload malformed content to inspect a durable
failed job and explicit retry behavior.

Start the seeded review. Demonstrate approve/reject/cancel in separate instances;
terminal transitions cannot repeat. Inspect durable audit/estimated usage as the
administrator. Switch to `viewer-a` and observe administrator restrictions and
cleared private history. Changing a source/identity cancels obsolete requests.

Stop the API only in the disposable test instance. The frontend retains a
connection error with Retry and explicit sample entry. Restart against the same
database and retry; no successful sample result is substituted automatically.

## Evidence to show in an interview

Show the [verification record](portfolio-verification.md), a real source drawer,
the first failed held-out quality report and the recorded regression/repair
sequence. Describe PostgreSQL/Redis as deferred live acceptance. Never describe
synthetic labels as human validation, the sample as connected execution, a
heuristic rank as probability, or source extraction as model reasoning.

No video or public deployment has been produced in this milestone. This script
and inspected screenshots are the local presentation package.
